## Step: write

Write one file, docs/<feature-name>.md, with these sections as `##` headings:

- Overview: what the change adds, in two or three sentences.
- Usage: each public function or API with its parameters, return values, and
  errors, plus one short example.
- Limitations: inputs it rejects, behavior it does not cover, and any open
  defects that the review findings in your input report.

Then call submit_documentation once, listing the file. Use INCOMPLETE if you
could not document the change accurately, and say why in the summary.
